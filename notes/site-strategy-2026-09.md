## 1. 前提：今のサイトには2つの人格が同居している

| | メイン（現行運用） | PR #34（未マージ・30記事シリーズ） |
|---|---|---|
| 名義 | ちー | Chiaki |
| トーン | 一人称の日記・素の言葉 | 「Chiakiくん」との対話形式（リベ大のふくぴー／リーマンくん構成に類似） |
| テーマ | 富山移住・子育て・畑・卵・日々の暮らし | キャリア形成・家計管理・資産運用（25〜30代女性向け） |
| カテゴリ | 現行5カテゴリ（`money-career`/`local-life`/`parenting`/`food`/`health`） | 旧カテゴリ（`資産運用`/`ライフスタイル`/`キャリア`）が大半、一部のみ新カテゴリに移行済み |
| frontmatter | `thumbnail`/`tags`/`draft` | `heroImage`のみ、`tags`なし |
| 収益志向 | 低い（日記としての記録が主目的） | 高い（テーマ選定からして収益化前提） |

**月収30万円という目標は、「ちー」の日記トーンのままでは実現が遠く、PR #34の資産形成・キャリア系コンテンツと組み合わせて初めて現実的になる。** 一方で、日記のリアルな体験談は信頼性（E-A-T）の裏付けとして非常に強い武器になる。

→ 結論：**「ちー（＝Chiaki）が、地方移住と共働き子育てを実体験しながら、お金と暮らしの選択を発信する」1つの人格に統合する。** 「Chiakiくん」との対話形式は使わず、既存の日記トーン（一人称・素の言葉）に寄せて30記事シリーズをリライトする方向を推奨（キャラクター対話形式は他者の構成に寄りすぎるため）。

## 2. ターゲット読者の再定義

現行の30記事シリーズの読者像と、日記記事の読者像を統合すると：

**メインペルソナ**: 25〜35歳、地方または地方移住を検討中の女性。共働き・子育て（または妊活〜出産）と、キャリア・家計管理の両立に悩んでいる。東京一極集中や「なんとなくの将来不安」に疑問を持ち始めている層。

この読者は以下のような検索行動を取る（想定）：
- 「地方移住 後悔」「東京 富山 移住 比較」
- 「妊娠 転職 タイミング」「産休 育休 手当 いくら」
- 「共働き 家計管理 貯金できない」
- 「保険 見直し 子育て世帯」
- 「キャリア 中断 復帰」

→ **集客記事（検索流入）と収益記事（保険・家計相談・転職エージェント等のアフィリエイト）の両方を、この1つのペルソナに向けて設計する。**

## 3. 収益モデルの検討（月収30万円の現実的な内訳）

リベ大ブログ教室の分類（AdSense／アフィリエイト／純広告）を踏まえ、chiyyy.comのテーマ（お金・キャリア・子育て・移住）に合う手段を検討：

| 手段 | 単価感 | chiyyy.comとの相性 | 備考 |
|---|---|---|---|
| Google AdSense | 低（PVで稼ぐ） | 中 | 月30万円をAdSenseだけで狙うと数十万PV/月が必要。現実的には補助的収入と位置づける |
| ASPアフィリエイト（保険・住宅・転職エージェント等） | 中〜高（1件数千〜数万円） | **高** | 「子育て世帯の保険見直し」「地方移住×転職」など、まさに扱っているテーマと直結。少ないPVでも成約単価が高い |
| 楽天/Amazon（もしもアフィリエイト） | 低 | 中 | 卵・畑・時短家事グッズなど「食・暮らし」カテゴリの記事と相性が良い |
| 情報発信の延長（コンサル・note等） | 高 | 低〜中（本人のキャパ次第） | 将来的な選択肢として保留 |

**現実的な試算の考え方**（あくまで仮説、リベ大の「1年で月収10万円」という実例を参考値として）：
- 月30万円は、月10万円達成の3倍規模。単純な記事量産だけでなく、**高単価ジャンル（保険・住宅・転職・資産運用系ASP案件）への集中**が必要。
- 目安として、月10万PV＋成約率0.5〜1%＋平均単価5,000円のASP案件で月20〜30万円は射程に入る（業界の一般的なレンジ。実際の数値は案件次第で大きく変動するため、A8.net等で具体的な案件の単価を必ず確認すること）。

## 4. サイト構造・コンテンツの改善案

### 4-1. カテゴリ・frontmatterの統一（最優先・技術的整理）
- PR #34の30記事すべてを、現行5カテゴリ（`money-career`/`local-life`/`parenting`/`food`/`health`）に再分類する。
- `heroImage` → `thumbnail`、`tags`の付与、`draft`フィールドの明示など、frontmatterを現行スキーマに統一する。
- 「Chiakiくん」との対話形式は、ちーの一人称トーンにリライトする（推奨。ただし工数が大きいため、段階的でも可）。

### 4-2. カテゴリごとの「まとめ記事」新設
リベ大の「まとめ記事＝ハブ」の考え方を応用し、5カテゴリそれぞれに入り口となるまとめ記事を作る。
- 例：「お金・キャリア」カテゴリのまとめ記事で、キャリア形成・保険・資産運用系の詳細記事へ内部リンクし、回遊率を上げる。
- まとめ記事自体がSEOで上位表示を狙えるキーワード（例：「共働き 家計管理 まとめ」）を意識する。

### 4-3. 収益記事（キラーページ）の新設
現状、日記・解説記事はあるが、商品・サービスへ誘導する「レビュー記事」「比較記事」が存在しない。
- 例：「地方移住者向けの家財保険を比較してみた」「子育て世帯におすすめの家計簿アプリを使い比べた」等、実体験ベースのレビュー記事を新設。
- リベ大のレビュー記事の型（共感→紹介→体験談→メリデメ→おすすめな人→今行動すべき理由）を参考に、独自の言葉で構成する。

### 4-4. キーワード選定の運用への組み込み
新規記事執筆時（`blog-post`スキル使用時）に、以下を追加する：
- 想定読者の検索意図を先に言語化する（既にスキーマにある「読者の検索意図をWebSearchで調べる」手順を強化）。
- ロングテール（3語以上の検索キーワード）を意識したタイトル・見出し設計。

## 5. PR #34の扱い（決定：リライトして統合）

対話形式（Chiakiくん）のまま取り込むのではなく、**ちーの一人称トーンにリライトしてから現行5カテゴリに統合する**方針とする。

理由：
- YouTube（料理・ライフスタイル）を今後始める予定とのことで、**発信者の人格を「ちー」1本に統一しておくことが、ブログ・YouTube双方の相乗効果につながる**（下記7章参照）。
- キャラクター対話形式は他者（リベ大）の構成に寄りすぎており、著作権・独自性の観点からも避けたい。
- 工数はかかるが、実体験ベースの一人称に直すことで、E-A-T（信頼性）が上がり、アフィリエイトの成約率にも良い影響が見込める。
- 段階的な移行でよい（全30記事を一度にやる必要はなく、アクセスが見込めるものから順にリライト）。

## 6. YouTube（料理・ライフスタイル）との連携

YouTubeでの発信予定を踏まえ、ブログとの役割分担を以下のように整理する。

| チャネル | 役割 | 強み |
|---|---|---|
| YouTube（料理・ライフスタイル） | 認知獲得・ファン化・信頼構築 | 顔・声が見える、感情に訴えやすい、拡散性 |
| ブログ（chiyyy.com） | 検索流入の受け皿・収益化 | SEOでの長期的な集客、アフィリエイトへの誘導、情報の網羅性 |

**連携方針**：
- 動画で紹介した料理・畑・暮らしのネタは、「食・卵・富山」カテゴリの記事として文字化し、動画を埋め込む（動画→記事、記事→動画の相互送客）。
- YouTubeの概要欄・固定コメントからブログへリンクし、逆にブログ記事内にもチャンネル登録の導線を置く。
- 料理・暮らし系の動画で「ちー」への信頼が積み上がった視聴者を、ブログの「お金・キャリア」系の収益記事（保険・家計・転職）へ自然に橋渡しする（例：「移住・子育ての暮らしぶり」を見た人が、「その暮らしを支えるお金の話」を読みに来る動線）。
- これにより、リベ大の記事でも触れられていた「SEOだけだと初期は読者が集まりづらいので、SNS（今回はYouTube）を併用する」という考え方を、chiyyy.comでも実践する形になる。

**留意点**：YouTubeチャンネルの開設・収益化条件（登録者数・視聴時間などYouTubeパートナープログラムの要件）は本人が別途確認・申請すること。

## 7. 実行ロードマップ（優先順位）

1. カテゴリ・frontmatterの統一（技術的整理、Claude Codeで対応可能）
2. PR #34の記事を、ちートーンへ段階的にリライトしながら現行カテゴリへ統合
3. カテゴリ別まとめ記事の新設（5本、Claude Codeで下書き可能・本人確認必須）
4. 収益記事（レビュー・比較記事）を1〜2本試験的に作成
5. **【本人作業】** [registration-checklist.md](./registration-checklist.md) に沿って Search Console/Analytics → ASP → AdSense の順で登録
6. YouTube開始後、動画⇔記事の相互リンクを組み込む
7. 3〜6ヶ月後、アクセス・成約データを見てリライト・改善サイクルに入る
